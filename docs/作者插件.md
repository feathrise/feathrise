# 作者插件

## 安装与生效

通过工程菜单中的插件管理器安装、更新、启停或移除作者插件。没有打开工程时可管理全局插件；打开工程后可选择全局或当前工程范围。

每个平台的插件交付一个动态库：Windows 为 `.dll`，Linux 为 `.so`，macOS 为 `.dylib`。安装时核对真实二进制格式、当前操作系统、编辑器进程架构和 ABI，不能仅按文件后缀判断。

全局根统一为 `~/.feathrise/plugins/`，工程根为 `<工程>/plugins/`。管理器显示当前范围的实际目录，点击路径可在系统文件管理器打开；切换全局／当前工程后，路径同步切换。同 ID 的工程副本优先，工程副本损坏或停用时不会悄悄回退全局。

没有打开工程时，全局安装、更新、启停和移除在后台事务完成后直接显示已生效，不必为完成安装先打开工程。打开工程后才创建插件作者会话；“已生效”不表示当前已装载 DLL。已有工程会话保留正在使用的版本和草稿，这时的变更明确提示“重新打开工程后生效”，不在运行中热卸载。失败仍显示实际错误并保留原文件与待处理计划。

当前格式将元数据内嵌在二进制中，不需要另附 `plugin.json`。已有旧目录包不能作为新的安装格式；显式确认移除时，只将受检的旧包归档保留，不删除作者数据。旧格式不能启用或直接更新；没有待处理计划时，“撤销待生效变更”不可用。禁用操作应有明确灰显，可用按钮提供悬停和按下反馈。

发现或加载失败会在右下角显示可关闭通知，点击“查看插件”可进入管理器查看完整原因。错误不会挤占顶部工具行，同一批错误也不会在关闭通知后反复弹出；管理器会继续保留真实的失败状态。

## 接入协议

`feathrise_plugin_api` 由共享库仓库独立提供并准备发布 crates.io，包含 C ABI、有界 JSON 快照和元数据工具；开发插件无需取得编辑器源码。工具入口、中央文档、右侧唯一预览、时间轴、地图领域及保存事务由宿主提供；具体领域数据由插件和工程自己的运行端解释。Rust／Bevy 对象不跨越二进制边界。

元数据包含格式、稳定 ID、工具名称、版本、目标系统／架构、ABI 主版本及运行依赖，静态保存在 PE／ELF 的 `.frmeta` 或 Mach-O 的 `__DATA,__frmeta` 中。扫描阶段只解析文件；真正加载时，宿主将 `feathrise_plugin_metadata_v1` 返回的字节与静态元数据核对，再使用 `feathrise_plugin_api_v1` 函数表。

接口包发布后，可用 `cargo install feathrise_plugin_api --version "=0.1.0" --locked --features reader --bin feathrise-plugin-meta` 独立安装静态检查命令。安装后查看插件元数据：

```powershell
feathrise-plugin-meta inspect <插件文件> --json
```

原生插件与编辑器处于同一进程，只安装可信来源。作者端单文件协议不等同于通用闭源运行端加载能力；工程运行依赖仍应由该工程明确管理，插件管理器不会自动改写 Cargo 或工程入口。
