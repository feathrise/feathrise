# 开发与验收

## 依赖与本地源码

公开 Cargo 清单通过版本号声明 SDK 依赖。当前源码构建按 [README](../README.md#从源码启动)检出固定修订的公开 SDK 与补丁仓，再用路径覆盖接入，不要求这些 SDK 包已发布到 crates.io。只有选择纯 registry 接入时，才需要 SDK 及其子包先完成发布；配套八项第三方补丁仍由消费工程显式配置，库包不能自动传递根工程的 `[patch.crates-io]`。

### 本地源码覆盖

编辑器、`feathrise_runtime/` 与 `feathrise_patches/` 同级检出后，将下面完整配置保存为编辑器内的 `.cargo/local-sdk.toml`。共 23 项 SDK 包和 8 项第三方补丁，路径以编辑器根目录为基准。编辑器自己的 `.cargo/config.toml` 会加载此文件；它已忽略，不依赖私有父仓库或用户目录配置。

这份覆盖用于编译编辑器。`sdk-source.toml` 则决定之后新建工程的来源，默认 `path` 同样使用这两个同级目录；修改它不会替换编辑器自身的 Cargo 依赖。公开 CI 独立检出公开依赖并生成覆盖，见 [Windows CI](ci.md)。

在编辑器目录先执行 `cargo fetch --locked` 获取锁定依赖，再运行定向检查：

```powershell
cargo check --locked -p feathrise_host -p feathrise_game_template -p feathrise_editor_map -p feathrise_editor_ui --tests
cargo test --locked -p feathrise_host --bin feathrise
```

测试字体通过 SDK 的公开 `DEFAULT_FONT_BYTES` 获取。需要文件路径的独占夹具自行写入这份字节，不读取 SDK 仓库内部文件。原生运行库身份通过轻量 `feathrise_runtime_manifest` crate 获取，默认编辑器无需为读取清单启用 DLSS 或安装厂商 SDK。

特性通过 Cargo `--features` 选择：`fsr` 启用 FSR 超分与帧生成候选，须先将 `FEATHRISE_FSR3_PACKAGE` 指向与 SDK 锁匹配的本地 Windows 原生 ZIP；可选 DLSS 帧生成需要额外厂商 SDK 与桥接构建环境。开发沿用已有 `target/` 和当前 profile，例行检查无需清缓存。

## 可选自有品牌构建

当前公开源码不附带 Feathrise 正式 Logo。未设置 `FEATHRISE_BRANDING_DIR` 时，编辑器正常构建，不内嵌正式 Logo，也不读取其他目录中的品牌文件。

需要自有品牌时，准备一个含以下两个文件的目录，并确保自己拥有使用和分发这些素材的权利：

| 文件名 | 构建用途 |
| --- | --- |
| `feathrise-mark.png` | 内嵌的界面品牌图片 |
| `feathrise.ico` | Windows 可执行文件图标 |

将 `FEATHRISE_BRANDING_DIR` 显式设为该目录的绝对路径，再执行原有构建命令。例如：

```powershell
$env:FEATHRISE_BRANDING_DIR = 'C:\my-branding'
cargo run --locked
```

设置后，两份文件都必须存在；目录不存在或缺少规定文件时构建会报错，不会静默改用其他品牌素材。恢复无 Logo 构建时，移除该环境变量并重新构建。此入口不提供正式 Logo，也不授予 Feathrise 的名称或标识使用权；既有副本和官方原版程序继续遵循[品牌使用条件](../THIRD_PARTY_NOTICES.md#feathrise-品牌使用条件)。

## 可选 Blender 地形同步

公开编辑器不携带地形保存所用的两份 Python 脚本，普通构建和地形 GLB 保存不要求 Blender 或独立 Python。需要同步同名 `.blend` 时，显式配置外部工具：

| 文件名 | 用途 |
| --- | --- |
| `从GLB生成同名Blend.py` | 从本次地形 GLB 暂存文件重建同名 Blend |
| `Blender保存时自动导出GLB.py` | 供重建入口复用的唯一 `save_post` 导出回调 |

将两份脚本放在同一目录，把 `FEATHRISE_BLENDER_TOOLS_DIR` 设置为该目录的绝对路径，再启动编辑器。例如：

```powershell
$env:FEATHRISE_BLENDER_TOOLS_DIR = 'C:\my-blender-tools'
cargo run --locked
```

只有显式指定可用绝对目录、两份脚本均为非空普通文件，且能找到本机 Blender 时才启用同步。未配置、目录不是可用绝对目录、缺少任一非空普通脚本或找不到 Blender 时，保存继续提交地形 GLB，跳过同步，不生成、改写或删除已有的同名 `.blend`。编辑器不自动查找其他脚本目录，也不自动下载脚本。

Blender 使用其自带 Python，无需另装独立 Python。完整工具链可用后，实际启动、导入、保存、插件验证或超时失败仍属于整个保存事务失败，沿用原有失败和回滚规则，不能改成仅保存 GLB 后报告成功。脚本调用仍在原后台保存事务内执行，主线程只非阻塞轮询。

## 函数体热更新工具

Windows 函数体热更新使用已验证的 `dx 0.7.9`，可通过 `FEATHRISE_DX_PATH` 指定外部工具。现有开发缓存中的工具位置继续兼容；本仓不自动下载或搬迁工具。

链接代理源码归本仓 `assets/hotpatch/原生热补丁链接代理.rs`，随固定资源清单编译内嵌。源码开发从编辑器资源根读取，安装版从同一内容身份的资源缓存读取；生成的链接代理仍进入所选工程构建缓存，不读取父仓库的 `tools/` 源码。资源搬移与缓存校验测试覆盖该文件，实际函数更新仍需对应的真实运行验收。

## 中性验收

真实窗口验收仅在显式 `validation` 下安装；普通构建不安装自动操作或故障注入。各场景只创建自己的新夹具工程，核对原交互、后台回执、保存落盘、重开和实际截图。

```powershell
cargo run --locked --features validation -- --native-report <新的绝对报告路径.json>
cargo run --locked --features validation -- --embedded-report <新的绝对报告路径.json>
cargo run --locked --features validation -- --embedded-build-cancel-report <新的绝对报告路径.json>
cargo run --locked --features validation -- --code-iteration-report <新的绝对报告路径.json>
cargo run --locked --features validation -- --export-report <新的绝对报告路径.json>
```

停止编译、代码迭代和导出入口有 Windows 平台条件；各报告只证明实际执行的范围。编译检查、内部输入及旧报告不替代实体键鼠、系统对话框、其他平台或完整人工验收。

导出默认场景核对 `output/` 与包的搬移运行；为本次进程设置 `FEATHRISE_EXPORT_VALIDATION_SCENARIO=custom-cancel-retry` 可追加自选目录、取消保留和重试流程。

## 工程自有插件场景

专属模型、规则、安装器和场景由工程仓库维护。需要原宿主内部控件的配套验收时，可在 `validation` 构建中将 `FEATHRISE_VALIDATION_EXTENSION` 设为外部 Rust 适配器的绝对路径。

适配器以宿主内部子模块编译，提供 `run(target, report, package)` 和 `install(app, project)`，分别接管 `--plugin-report` 及作者实例的验收安装。它依赖对应宿主源码版本，不是稳定作者插件 ABI。构建脚本只在显式 `validation` 下读取配置并监听适配器子模块；普通构建忽略该变量。

默认公开构建没有适配器，也不读取工程仓库。未配置时 `--plugin-report` 明确报错，不生成成功报告。通用插件协议、管理器、保存及中性作者回归仍在本仓维护；工程负责其夹具及验收证据。
